## 8 · MERGE HAZARDS

**8.1 · Three name collisions.** `addToQueue`, `openLightbox`, `closeLightbox`
exist in both files with different jobs. s72's `addToQueue(siloId, effectId)`
pushes a two-field row; b2's `addToQueue()` reads no arguments and builds the
whole payload item from module state. They cannot coexist. The merge is: s72's
signature and call sites survive, b2's body is folded in as the payload
builder. Its 93 lines are the highest-value lines in b2 and the easiest to
break silently.

**8.2 · One writer for the rail button.** s72 declares `labelGo()` the sole
writer of `tbcGo`'s label, with the reason in a comment. b2's `updateActionBar`
(92 lines) does the same job for `queueAddBtn`. Do not port it. `updateRunGate`
comes across because it controls the button's *enabled* state, which `labelGo`
does not touch.

**8.3 · The payload needs almost no UI.** Read from `addToQueue` at 7812:

- `scale` is already the constant `'auto_85'` — the control is retired.
- `location` is `MATERIAL_LOCATIONS[preset]`, falling back to that table's
  first entry. No picker required.
- `style_id` is `'artists_gallery'` when the silo is `artists_gallery`, else
  `'realistic'`. Derives from `siloId`, which s72 already carries.
- `preset` is the effect id, which s72 already carries.
- `aspect_ratio` is sent and ignored by the route.
- `framing` is not sent at all.

## 9 · ONE LIVE BUG IN s72

`removeFromQueue` (HTML line 2711) ends with:

```js
if (card && card.dataset.silo === silo) card.classList.remove('is-selected');
```

`silo` is not bound in that scope. The only binding is a `var` inside
`openSilo`. Removing a queued effect while its card is on the floor throws
`ReferenceError: silo is not defined`, and the row is already gone by then, so
the queue and the floor disagree from that point on.

The boot gate did not catch it because it is on a path the gate does not drive.
The fix is one identifier — `it.siloId` is in scope at the call site. Worth
adding a gate that drives remove-with-card-visible.
