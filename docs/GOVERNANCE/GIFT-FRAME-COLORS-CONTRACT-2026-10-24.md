# Customer-selected frame colour (Gift Shop only): backend contract for Codex 1, 2026-10-24

Backend only, committed locally. Supersedes the "sold in natural" finish decision in GIFT-BEAUTY-SCENES-CONTRACT-2026-10-24.md section 4 (`GIFT_FRAME_COLOR` is gone): **every frame product's default is black again**, the customer may choose another colour per line. No price changed. No paid generation, order, deployment or Prodigi submission.

## Supported colours (exact Prodigi values, checked per SKU: `scripts/check-prodigi-frame-colors.ts`, sandbox, 174 product x colour combinations, all listed with the catalog print area; sampled quotes accepted at the same cost)
- **Classic Frame** (`framed:*`) and **Matted Frame** (`matted:*`): `black` (default), `white`, `natural`, `brown`, `dark grey`, `light grey`, `gold`, `silver`.
- **Framed Canvas** (`framed_canvas:*`): `black` (default), `white`, `natural`, `brown`, `gold`, `silver`.
- **One exception, reported not guessed: `matted:8x12` has only black, white, natural, brown, gold, silver.** Prodigi lists dark grey and light grey for it but with a 1500 x 2700 print area (every other colour 1800 x 3000), so the catalog geometry would be wrong for them.
- Prints, canvas, mug, card: no colour (`frameColors: null`; sending one is `400 invalid_frame_color`).
Always read the list from the response (`products[].frameColors.supported`), never hard-code it. The matted mount stays Snow white (fixed by Prodigi).

## Contract
- `PUT /api/v1/gift/sessions/{id}/lines`: each line may carry `frameColor` (string) and `acceptFinish` (boolean). Absent colour = `black` for a frame product. `400 invalid_frame_color` `{supported:[...]}` for a value not in that product's list or any colour on a product that has none. Stored and returned as `SessionView.lines[].frameColor` (frame products only); restored with the session; lines saved before this existed read as black.
- **Binding a picture to a frame line needs the colour stated**: a line with `generationId` and no `frameColor` is `400 finish_required` (black must be sent explicitly).
- **The finish is part of the approval.** The composition made when a generation is bound carries `plan.frameColor`. Changing a bound line's colour: the old composition is superseded and the generation binding is DROPPED (the line is unbound, black/other colour kept) unless the request re-sends the `generationId` AND `acceptFinish: true` ("the customer explicitly accepts this finish for this picture"); re-sending the generation without it is `409 finish_not_accepted`. Quantity changes keep colour and binding. The one free post-purchase correction keeps the finish.
- `AvailabilityView.products[].frameColors` = `{ supported: string[], default: 'black', selected: string } | null` (`selected` = this session's line of that product, else the default).
- `GET .../product-preview?productId=&generationId=&frameColor=`: `frameColor` is validated the same way (`400 invalid_frame_color`), part of the preview identity and every cache key (another colour is another preview, `url` and `beautyInput.url`), and echoed as `frameColor` on the response. The preview image itself is the picture; the colour only matters for the beauty scene.
- **Beauty frame recolour.** Frame scenes (Classic Frame, Matted Frame, Framed Canvas; 9 scenes) are routed for ANY supported colour, because the supplied frame mask lets the browser recolour the photographed natural-oak frame. `beauty.frame` = `{ selected, supported[], recolor: { mask: 'frame-mask.svg', folder, photographedColor: 'natural', toColor: selected, needed: selected !== 'natural' } }` (on `availability.products[].beauty` and on the product-preview response). Only the frame changes: the mat, glass and picture are untouched, and orientation and opening fit are checked exactly as before (the matted rectangles' mount openings are still not 2:3, so they still have no scene, in any colour). The Classic Frame is now routable (it was not while the scenes were natural and it was black).
- Checkout: the quote, the frozen order snapshot (`frozen.product.attributes.color`), the composition pin (`frozen.composition.frameColor`) and the Stripe line carry the selected colour; a composition approved for another colour does not sell the line (`409 compositions_not_approved`). A reused unpaid order refreshes its snapshot when the colour changed.
- Final Approval and the print source refuse a finish mismatch between what was approved, pinned and sold (`409 finish_not_accepted` / `gift_finish_changed`).
- **Fulfilment** places the attributes FROZEN into the order (`soldAttributes`), so the customer's colour reaches Prodigi, and every order sold before this (frozen black) is unchanged. A malformed snapshot can never add or drop an attribute; no snapshot (Print Shop) = the SKU map, exactly as before.
- **Print Shop unchanged**: its Classic Frame stays black, its catalog response has no colours, Gift-only families stay `selectable:false` there.
