### `credits` semantics

Read from `credit_balances.balance` keyed on `owner_key = user.id` —
`app/api/v1/auth/me/route.ts:32-36`. Three outcomes:

- row present, numeric → that balance (`:41-42`)
- no row → `0`, treated as a real state (`:43-47`)
- read error or throw → `null`, logged not thrown (`:38-40`, `:48-50`)

`null` means "unknown", not zero — the masthead is expected to render nothing
rather than a zero (`app/api/v1/auth/me/route.ts:15-17`). Read-only; nothing
here spends or grants (`:19-20`).

### Against Rich's live spot-check of 3 Sept

**No discrepancy found.** Magic-link sign-in is initiated client-side and
`/auth/callback` exchanges the code for a session —
`lib/store/auth.ts:5-8`. Once that cookie exists, `GET /api/v1/auth/me`
returns `{ user, credits }` as above. The code matches the observed behaviour.

Related, for completeness: `POST /api/v1/auth/signin`
(`app/api/v1/auth/signin/route.ts`, 58 lines) and `POST /api/v1/auth/signout`
(`app/api/v1/auth/signout/route.ts`, 62 lines).
